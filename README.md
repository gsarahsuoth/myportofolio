### Assignment 2

1. When a user opens the new portfolio page, the request is first received by portofolio/urls.py, which acts as the main entry point (or 'gate') of the project's routing system. This root URL configuration then delegates the request to the application's local routing in main/urls.py, where the path is matched to a more specific endpoint. Once the request path is matched, the corresponding view function in main/views.py is executed. Here, views.py acts as the main controller, handling the business logic between the database and the presentation layer. Inside the view function, the required data is retrieved from the database using the Model (main/models.py), which abstracts the data layer. After fetching the data, the view passes it inside a context dictionary to the HTML template (education.html). The template serves as the presentation layer, using Django Template Language (DTL) to dynamically render the data into HTML structure. Finally, after the rendering process is complete, the render() function returns an HTTP Response (with a 200 OK status) to send the final web page back to the user's browser.

2. Storing data in a Model instead of hardcoding it directly into an HTML template is essential because it separates data logic from layout and structure, following Django's MVT pattern. Models handle data management, while Templates focus purely on presentation. Using a Model allows for dynamic data rendering through loops ({% for %}) and gracefully handles empty states ({% empty %}). Furthermore, storing data in a database significantly improves maintainability and scalability, making it easy to add features like filtering, searching, and sorting in the future. In contrast, hardcoding data directly in HTML makes updates tedious, risks breaking template structure, and would require rewriting the application to support future enhancements.

3. In Django, makemigrations acts as the planning phase, while migrate acts as the execution phase. The makemigrations command changes in models.py and generates blueprint migration files without 'touching' the actual database, whereas migrate applies those recorded operations to update the database schema. An example of a model change requiring both commands is adding a new gpa field to an existing Education model. First, I would add the gpa field inside the Education class in models.py. Next, I would run python manage.py makemigrations to generate a new migration file based on the updated model. Finally, I would run python manage.py migrate to apply that migration file and update the database table.

1. We use Django’s ModelForm because it allows us to create forms directly from our Django models, so Django can automatically handle the form fields, validation, and saving the submitted data instead of us having to build everything manually in HTML. This makes the code simpler and keeps the form consistent with the database model. We also need {% csrf_token %} in forms that use POST because it protects the application from CSRF attacks by making sure the request actually comes from our own website.

2. JSON is preferred in modern web applications because it is lightweight, easy to read, and easier for applications to process compared to XML. Its structure is also similar to common data structures used in programming languages, such as objects in JavaScript and dictionaries in Python, which makes it convenient for transferring data between the frontend and backend. XML can also represent structured data, but it usually requires more tags and is more verbose, so JSON is often more practical for APIs and web applications.

3. When a view function returns portfolio data in JSON format, it first retrieves the data from the Django database through a model query. Since Django model objects are Python objects and cannot be directly converted into JSON, we need to perform serialization, which converts the model objects into a JSON-compatible structure containing the relevant fields. The serialized data can then be returned by the view as JSON, allowing the frontend or another application to easily receive and process our portfolio data.
